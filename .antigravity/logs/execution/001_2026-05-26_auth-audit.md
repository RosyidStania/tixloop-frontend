# Audit Report & Technical Debt: Auth Integration

## Audit Summary
- Frontend route structure for authentication (`login` & `register`) has been reorganized into an `(auth)` group.
- The `handleLogin` and `handleSubmit` functions successfully connect to `http://localhost:8000/api/v1/auth/login` and `/api/v1/auth/register` endpoints.
- Basic payload structure aligns with `RegisterRequest` and `LoginRequest` defined in the backend.

## Technical Debt Report
- **Environment Variables**: API URL is currently hardcoded in components instead of using environment variables (e.g., `PUBLIC_API_URL`).
- **Error Handling**: Still relying on browser `alert()`. It would be better to implement a Toast component or inline validation error messages from backend's `422 Unprocessable Entity` responses.
- **State Management**: Token is stored in `localStorage` directly in component. A centralized auth service/store in SvelteKit is recommended for maintainability.

## Next Feature Recommendation
- Implement a global HTTP interceptor or SvelteKit `hooks.client.js` to attach the Bearer token automatically to authenticated requests.
- Implement session check on mount (e.g. `+layout.svelte`) by calling `/api/v1/auth/me` to set global user state.
